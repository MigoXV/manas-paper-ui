# MANAS 验证与交付

## 使用硬门槛

以下任一项失败时，不得宣布任务完成，也不得用视觉完成度抵消：

1. 页面展示错误、过期或虚构的业务状态、数据或结果文案。
2. 核心任务无法完成，失败、暂停或中断没有与真实能力一致的恢复路径。
3. 关键流程不满足 WCAG 2.2 AA，或键盘、焦点、语义、对比度、缩放、触控和 reduced-motion 存在阻断问题。
4. Review 修改了文件，Refine 擅自迁移结构，或任务修改了未授权的共享组件、壳层和上游契约。

硬门槛通过后，再定性复核信息层级、密度、页面范式、主题一致性、响应式行为和代码整洁。

## 分层验证

根据项目能力逐层执行，不用低层检查代替高层验证：

### 1. 静态与工程检查

- 运行目标仓库规定的 lint、类型检查、构建和相关测试，不写死包管理器或命令。
- 搜索被替换的组件、选择器、资源和演示数据，确认没有悬空引用或旧视觉残留。
- 检查浏览器支持、主题 token、可访问名称、语义标签和条件渲染。
- 检查行动强调、选择、业务状态与领域语义色没有混用；领域颜色映射在相关组件之间一致且存在非颜色冗余。
- 检查页面使用了 `control-specifications.md` 的默认控件关系，或为每项偏离保留了真实任务、成熟项目体系或输入方式依据。

### 2. 状态与交互检查

- 按页面状态矩阵覆盖默认、加载、空、成功、失败、重试、禁用、权限受限和陈旧数据中实际存在的状态。
- 完整走通主要任务、取消或返回、危险动作确认、失败恢复和刷新后的稳定状态。
- 确认主操作常显，渐进展示的次要操作可由键盘与触屏到达，禁用操作能解释原因。
- 对输入、选择、筛选和参数控件检查 default、hover、focus-visible、filled、invalid、disabled 与 read-only 中实际存在的状态；确认静止状态安静，操作与错误状态清楚。
- 检查更新中的数值、时间、长文本和列表增删是否造成布局跳动、焦点丢失或错误播报。
- 对具有发布或部署生命周期的对象，走通草稿、保存、校验、发布、接入、测试和恢复中实际存在的阶段，确认失败不会替换仍有效的稳定版本。
- 对空间编辑器检查初次布局、已有布局、节点增删、拖动持久化、无效连接、自动排列、适配视野、缩放平移、检查器开关和布局失败恢复。

### 3. 视觉、主题与响应式检查

- 在项目支持的宽、中、窄条件检查真实页面；项目没有基准时至少抽查约 320、768、1280px。
- 检查项目已支持的所有主题、200% 缩放、长翻译、中文换行、空内容、极端长内容和虚拟键盘影响。
- 检查横向溢出、滚动归属、粘性或固定动作遮挡、抽屉焦点、表格降级和布局稳定性。
- 有截图或视觉回归设施时保存并比较关键状态；没有设施时进行人工页面检查，不伪造截图结论。
- 跨代表性路由检查产品语法是否稳定：应用壳层、对象身份、局部导航、主任务区与持久状态不应无任务依据地跳位。空间编辑器还需检查节点重叠、连线遮挡、画布面积和两侧面板竞争。
- 检查白色填充、完整边框、大圆角和过高尺寸没有在普通控件上无依据叠加；筛选、短参数、长内容与主要动作没有被机械等宽或为填满页面而拉伸。

### 4. 无障碍检查

- 用键盘完成核心路径，确认可见焦点、合理顺序、跳过重复区域和焦点返回。
- 检查标题层级、landmark、标签、错误关联、状态播报和图标按钮名称。
- 使用可靠工具验证文本、控件与状态对比度；不以“看起来清楚”代替测量。
- 检查 pointer target、触屏等价入口与 `prefers-reduced-motion`。关闭动画后仍需保留必要反馈。
- 确认透明或低高差控件仍有可辨识边界，焦点环不会被裁切，错误文字与字段正确关联，disabled 与 read-only 不只依赖低透明度区分。
- 在空间编辑器中检查节点、端口、画布控制与检查器具有可理解名称；领域语义色关闭或无法辨认时，标签、图例和结构仍能表达类型关系。

无法启动页面、缺少状态数据或没有相应测试设施时，明确标记“未验证”，说明原因和建议验证方式。不得把 lint 或 build 通过描述为视觉、交互或无障碍已验收。

## Review 交付契约

按严重度输出发现，先给结论，再给证据：

- **阻断**：违反硬门槛，可能造成状态欺骗、任务失败、数据风险、关键无障碍失败或越权修改。
- **重要**：明显损害理解、效率、响应式或 MANAS 层级，但不直接阻断核心任务。
- **建议**：视觉润色、轻微一致性和安全的局部清理。

每项包含文件与位置或运行状态、可观察证据、用户影响、建议模式和最小修复范围。没有发现时也要说明检查范围与残余未验证项。Review 不生成补丁，不把偏好写成事实。

## Refine、Migrate 与 Create 交付契约

最终报告依次包含：

1. 完成的用户可见结果与保持不变的关键行为。
2. 主要结构、状态、无障碍和视觉修改。
3. 实际执行的检查及结果。
4. 未验证项、已知限制和未获授权的上游问题。

不要用文件清单取代用户结果，不声称执行了未运行的检查。删除任何实质内容时说明删除范围、引用检查和恢复方式。

## 前向测试验收

修订本技能时，使用隔离任务覆盖 Review、Refine、Migrate、Create 和不同页面范式。只向测试代理提供技能、用户请求与原始页面证据，不泄露预期答案或本次修订意图。

检查测试结果是否：

- 选择正确模式并遵守写入边界。
- 先理解状态与目标项目设计系统，而不是套用 React、固定分栏或统一 token。
- 在表格有真实比较价值时保留表格。
- 将窄屏视为任务重排，而不是机械堆叠。
- 能识别空间编排与结构化编辑器，不会为了连续表面删除合理的画布边界、节点容器、类型图例或上下文检查器。
- 能抽象案例中的产品语法、领域语义和生命周期关系，而不会强制复制左侧栏、具体色板、固定尺寸或英文眉题。
- 发现上游或共享问题时报告并请求范围，不擅自修改。
- 区分工程检查、运行验证和未验证项。

测试产物不得留在技能目录中。真实案例可用时，再以用户认可的页面校准定性规则。
