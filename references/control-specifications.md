# MANAS 控件规范

## 使用方式

将本规范作为 MANAS 页面中输入、选择、筛选、短参数与按钮的默认设计起点。目标项目已有成熟组件体系时，优先映射其 token 与变体。对于没有外部视觉规范依据的组件库默认外形，若厚重白底、完整深边框或大圆角破坏低噪声层级，不能仅以“复用组件库”为由保留；无差别等宽布局则应依据真实字段语义检查。

本文件受 `SKILL.md` 的外部视觉系统优先级约束：语义分型与宽度关系继续适用，尺寸、表面、边界、圆角和按钮外观优先服从外部规范。外部系统明确规定的外观不能因与 MANAS 默认值不同而被判为问题；组件库未经设计的默认外形不等于外部规范。

这些值不是跨项目不可覆盖的常量。只有真实内容、任务密度、输入方式或成熟设计系统提供更合适的关系时才调整，并保持“静止安静、操作显现、语义有层级”的结果。

## 默认视觉规格（无对应外部规范时）

- 将常规文本输入、搜索框、选择控件和同级按钮的桌面视觉高度设为 42–44px。
- 将普通输入控件圆角设为 5–6px。只为状态标签、短筛选或确有胶囊语义的对象使用全圆角；不把 8–12px 的常见 SaaS 圆角作为默认输入语言。
- 使用透明背景或与页面画布非常接近的极浅表面色。只有表面关系确实需要时才使用白色，避免连续出现“白底＋完整边框＋大圆角”的塑料块。
- 使用安静的 1px 默认边界。让 hover 轻微加深，让 `focus-visible` 使用清楚的焦点边界或焦点环；错误、禁用与只读状态分别表达。
- 让标签、当前值和状态先于矩形轮廓被感知。不要同时依赖高亮填充、深边框、大圆角和过高尺寸制造可操作性。
- 保持实际命中区域、焦点可见性、文字和边界对比度满足目标项目采用的 WCAG 2.2 AA 要求。视觉降噪不得让控件消失、焦点模糊或触控困难。

## 语义分型与宽度

在布局前区分以下角色，不要因为它们都可编辑就使用同一种等宽 Input：

- **查询与筛选**：名称、Speaker ID、Channel ID、关键词和枚举条件。使用与预期内容长度相称的中等宽度，保留清楚标签与当前值。
- **短检索参数**：相似度、阈值、Top K、数量、页数和步长。使用紧凑的数字输入、选择或步进控件，宽度只需容纳有效值、单位和必要操作。
- **布尔与有限选择**：根据选项数量与语义使用开关、复选、单选、分段控件或 Select，不机械降级为文本框。
- **长内容**：URL、路径、描述、提示词与确需完整浏览的标识。根据阅读、复制和校验需要扩展宽度，必要时独占一行。
- **主要动作**：按真实结果命名并保持可发现；不要通过放大所有相邻输入来与按钮对齐视觉重量。

让宽度由数据类型、预期长度、操作频率和任务重要性共同决定。不要默认使用等分网格或让每个字段 `flex: 1` 填满整行；允许主动留白。窄屏按任务顺序换行或纵向排列，不把紧凑参数压缩到不可操作。

## 状态层级

- **默认**：提供足以识别输入区域的浅边界或轻微表面差，不主动争夺注意力。
- **Hover**：只增强必要的边界或表面反馈，不产生明显位移。
- **Focus**：使用清晰的 `focus-visible` 反馈，并保持标签、帮助与错误关联可读。
- **Filled**：当前值是视觉主体；不要仅因已有值就提升整个容器的重量。
- **Invalid**：在控件附近提供错误文字和恢复路径，颜色只作补充。
- **Disabled / Read-only**：明确区分不可操作与只读可复制；不要统一用极低透明度处理。

## 相似检索校准

相似检索工具栏可以采用“两个中等宽度筛选字段＋两个紧凑参数控件”的关系：Speaker ID、Channel ID 负责缩小结果范围；最低相似度、Top K 负责调整检索行为。保持同一行基线和一致状态语言，但不要让四个控件等宽、铺满或获得相同视觉重量。

此例只固定语义关系和默认控件语言，不固定业务文案、绝对列宽或特定框架实现。

## 反模式

- 直接保留组件库默认的大白底 Input，并只调整页面外围样式。
- 将筛选、数字参数、长文本和主要动作全部画成等高、等宽、等圆角的矩形。
- 为填满横向空间无意义地拉长 ID、阈值或 Top K。
- 以透明背景为由移除所有边界，或以视觉轻量为由削弱焦点、错误与禁用语义。
- 为修复单页覆盖全局 Input token，导致其他页面出现未经验证的回归。
